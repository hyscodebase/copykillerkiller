# 문서 유형별 글쓰기

## 메모에서 문장으로

1. **문서가 해야 할 일을 한 문장으로 정한다.** 독자가 무엇을 이해하거나 결정해야 하는지 확인한다. 작성 목적, 독자, 문서 유형, 꼭 남겨야 할 내용이 이미 주어졌으면 바로 진행한다. 꼭 필요한 사실이 빠졌다면 핵심 질문을 남기고, 나머지 부분은 작성할 수 있는 범위에서 진행한다.
2. **자료와 작성자의 판단을 연결한다.** 사용자가 준 메모·관찰·자료에서 쓸 사실, 제안, 해석, 확인할 항목을 나눈다. 수치와 인용은 해당 출처에 연결하고 적용 범위와 시점을 같이 확인한다. 사용자가 준 정보와 원자료에서 직접 확인한 사실을 구분한다. 문서의 결정을 바꾸는 미확인 정보는 `[확인 필요]`로 표시하거나, 확인할 질문으로 따로 남긴다. 작성자가 겪은 일, 인터뷰, 평가 결과, 승인 상태는 제공된 정보에 근거해 쓴다. 허구를 요청받으면 가상 사례나 창작의 맥락을 분명히 한다.
3. **독자에게 필요한 순서로 쓴다.** 첫 문장에서 핵심 판단이나 목적을 제시하고, 뒤에서 근거와 조건을 설명한다. 문단의 역할이 다르면 나눈다. 추상적인 문장은 확인할 수 있는 자료, 판단이나 다음 행동으로 구체화한다. 분량을 줄일 때에도 수치의 분모, 적용 대상, 조건은 함께 남긴다.
4. **원고와 자료로 다시 확인한다.** 수정 전후의 의미, 확신 정도, 수치, 날짜, 책임 주체와 인용이 일치하는지 본다. 다른 문단을 읽어야 주장이 이해된다면 필요한 연결을 보완한다. 비슷한 설명은 한 곳에 두고, 문장 길이와 말투는 독자와 내용에 맞게 조절한다. 사용자가 글의 예시를 주면 어휘와 격식을 참고하되, 그 예시의 사실이나 경험을 새 원고로 옮기지 않는다.

초안이 확인된 메모나 원자료와 다르면 근거가 있는 내용으로 고치고 이유를 남긴다. 자료끼리 충돌하면 어느 부분이 다른지 표시하고 작성자가 확인할 수 있게 한다.

## 유형에 따라 달라지는 기준

| 문서 유형 | 우선 확인할 내용 | 구성의 출발점 |
|---|---|---|
| 학술 글·실험 보고서 | 주장, 실제 자료, 측정 단위와 분모, 방법의 범위와 한계 | 질문 → 관찰·출처 → 해석 → 남은 검증 |
| 기술 문서·업무 보고 | 확인한 현상, 실제 조치, 확인 범위, 남은 문제 | 현황 → 근거 → 결정 또는 다음 단계 |
| 기획안·제안서 | 해결할 문제, 제안한 방법, 사용자가 제시한 조건과 승인 상태 | 문제 → 제안 → 실행 조건 → 평가 기준 |
| 공지·이메일 | 독자가 해야 할 행동, 확정된 시점·장소, 회신 대상 | 배경 한 줄 → 핵심 요청이나 안내 → 필요한 조건 |
| 에세이·자기소개 | 작성자가 제공한 장면, 맡은 역할, 관찰과 본인의 해석 | 실제 상황 → 선택과 행동 → 의미 |

유형이 섞이면 읽는 사람이 가장 먼저 해야 할 판단을 기준으로 순서를 고른다. 학술적인 말투를 모든 문서에 적용할 필요는 없다. 사용자가 요청한 언어로 쓰고, 번역이나 표현 수정을 할 때도 이름, 단위, 용어와 사실의 확신 정도를 유지한다.

## 가상 예시

**업무 공유.** 메모에 “오전 배포 뒤 결제 버튼 오류 6건, 모두 iOS 18. 담당자가 로그 확인 중. 원인과 복구 시각 미정”이라고 적혀 있다면 다음처럼 쓸 수 있다.

> 오전 배포 후 iOS 18에서 결제 버튼 오류 6건이 확인됐습니다. 담당자가 로그를 확인하고 있습니다. 복구 시각은 미정입니다.

**실험 보고서.** 메모에 “같은 시료 12개를 처리 전후로 비교, 대조군 없음, 처리 뒤 9개에서 값이 낮아짐”만 있다면 다음처럼 쓸 수 있다.

> 처리 뒤 12개 시료 중 9개의 측정값이 낮아졌다. 이번 관찰은 대조군 없이 같은 시료를 전후로 비교했으므로, 감소의 원인을 판단하려면 추가 비교가 필요하다.

**이메일.** “팀 회의를 수요일에서 목요일 오후로 옮길 수 있는지 묻기. 장소와 시작 시각은 미정”이라면 이동을 확정한 것처럼 쓰기보다 목요일 오후에 가능한 시간을 회신해 달라는 요청을 중심에 둔다.

## 결과 전달과 검사 비교

- 새 문안을 요청하면 복사해 쓸 수 있는 본문을 제공한다. 확인이 필요한 질문이나 자리표시는 필요한 경우에만 별도로 정리한다. 검토만 요청하면 위치와 이유, 작성자가 확인할 근거를 적는다.
- 실제 검사 결과를 비교해 달라는 요청에는 각 파일의 판본, 검사 유형·설정과 시점을 연결한다. 과거 보고서의 수치를 새 문안에 붙이지 않는다. 여러 유형을 비교하려면 유형별로 전후 판본을 짝지어 기록하고, 점수가 내려간 경우와 같거나 높아진 경우를 함께 보고한다. 결과는 확인한 문서와 검사 조건의 범위에서 해석한다.
