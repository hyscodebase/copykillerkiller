# DOCX 보존 및 검증

## 사본에 수정 적용

1. 원본 경로와 SHA-256을 기록한다. 다른 폴더 또는 다른 이름으로 결과물을 저장한다. 과제에서 파일명을 지정했다면 폴더를 달리해 이름을 유지할 수 있다.
2. 수정할 문단의 위치와 기존 문장을 확인한다. 앞쪽 문단이 추가·삭제되면 인덱스가 바뀌므로 위치와 문장을 함께 대조한다. 동일 문장이 여러 번 나오는 경우 앞뒤 문장과 절 제목을 쓴다.
3. 수정이 필요한 실행 구간의 텍스트만 바꾼다. 서식이 섞인 문단, 하이퍼링크, 수식, 각주 참조, 필드를 한 실행 구간으로 합치지 않는다. 단순한 문단도 문단 스타일과 속성을 유지한다. 전면 재생성은 사용자가 요구한 형식 변경에만 적용한다.

## 결과 확인

수정 사본을 만든 뒤 아래 명령으로 내부 파일과 보호 요소를 비교한다. `<스킬 폴더>`에는 현재 읽고 있는 `SKILL.md`가 들어 있는 경로를 넣는다.

```sh
python3 "<스킬 폴더>/scripts/verify_docx.py" "원본.docx" "검토용 사본.docx"
```

결과의 `source.sha256`을 편집 전에 기록한 원본 해시와 대조한다. `zip_parts`에서 변경된 내부 파일을, `protected_document_xml`에서 표·수식·구역·링크·필드 등의 변화 여부를 확인한다. 변화가 있다면 요청한 수정으로 설명되는지 확인한다. 본문 인용의 의미와 화면 배치는 아래 절차로 별도 확인한다.

- 결과 DOCX가 열리는지 확인하고, 수정 전후 본문을 대조해 요청된 변경만 들어갔는지 확인한다.
- 서식 보존이 필요한 작업에서는 DOCX 내부 파일의 차이를 점검한다. 표, 수식, 구역, 목차 필드, 링크, 참고문헌, 각주, 고지문 중 해당 요소를 비교한다. 변경된 항목의 개수뿐 아니라 필요한 내용과 참조도 확인한다. 주석 전용 결과에서는 주석 앵커를 제외한 본문이 같은지 확인한다.
- 최종 DOCX를 렌더해 전체 페이지의 한글 글꼴, 줄바꿈, 페이지 넘김, 표·수식 배치와 잘림을 확인한다. 이전에 검토한 렌더와 이미지가 같은 페이지는 그 비교로 확인할 수 있다. 렌더가 불가능하거나 대체 글꼴을 사용했다면 확인한 범위를 결과에 적는다.
- PDF도 요청받았다면 검증한 최종 DOCX에서 내보내고 해당 PDF의 페이지와 텍스트를 확인한다. 이전 렌더를 새 결과로 전달하지 않는다.

작업 로그에 원고나 검사보고서의 개인정보가 남을 수 있다. 예제나 배포용 스킬에 원본, 실제 검사번호, 개인 경로, 발췌문을 포함하지 않는다.
