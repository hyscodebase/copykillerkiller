# 전처리 실행과 결과 해석

## 실행

아래의 `<스킬 폴더>`를 현재 읽고 있는 `SKILL.md`가 들어 있는 폴더로 바꾼다. 경로에 공백이 있으면 따옴표로 감싼다.

```sh
python3 "<스킬 폴더>/scripts/prepare_review.py" "상세 결과.pdf" "원고.docx" "다른 판본.docx"
```

원고 한 개부터 실행할 수 있다. `Python 3.9+`가 필요하며 PDF 입력에는 Poppler의 `pdftotext`도 필요하다. 이미 배치가 보존된 UTF-8 추출 텍스트를 가지고 있다면 PDF 대신 `.txt`를 쓸 수 있다. 페이지 사이의 폼 피드(`\f`)를 유지한다. 없으면 추출 텍스트의 위치를 PDF의 실제 쪽수로 인용하지 않는다.

두 스크립트는 입력을 읽고 JSON을 표준 출력으로 전달한다. 보고서 대조 결과에는 문장 발췌, 파일 이름, 검사번호를 싣지 않는다. `draft_index`는 입력 원고의 순서다. 작업 결과를 별도 파일에 저장한다면 공개 저장소 밖에 둔다.

## 읽는 순서

| 결과 항목 | 다음 행동 |
|---|---|
| `report_summary` | 알려진 요약표에서 수치를 읽었으면 PDF 표지와 대조한다. `extracted`는 텍스트 추출 상태다. 그 밖의 상태에서는 요약표를 직접 확인한다. 의심 영역 수로 AI작성률을 계산하지 않는다. |
| `marker_candidates` | `page`와 `line`은 배치 텍스트의 표지 후보 위치다. PDF 화면에서 실제 표시인지, 구간이 어디까지인지 확인한다. |
| `drafts[].full_block_matches` | 본문 문단·표 셀 중 비교용 정규화 후 한 페이지 안에서 전체가 일치한 예시다. `full_block_match_count`를 함께 보고, 판본을 구분하는 여러 문장을 비교한다. |
| `drafts[].marker_matches` | `unique`는 한 원고 안에서 시작 문구가 한 번 일치했다는 뜻이다. `start`와 `end`는 그 문구가 걸친 XML 문단 경로이며, 표시 영역의 끝을 뜻하지 않는다. `body/tbl[1]/tr[2]/tc[1]/p[1]`은 첫 표의 두 번째 행, 첫 셀, 첫 문단이다. |
| `ambiguous`, `unmatched`, `insufficient_text` | 각각 원고 안 여러 위치와 일치, 해당 문구를 찾지 못함, 비교할 문구가 부족함이다. 앞뒤 고유 문장과 절·표의 순서를 확인한다. |
| `blank_text_pages` | 스캔 페이지나 텍스트가 없는 페이지를 화면에서 확인한다. |

표 순서, 문서 필드, 수식, 머리말과 각주 등은 Word 본문 텍스트와 PDF에서 다르게 나타날 수 있다. 첫 문장만 일치하거나 두 후보가 같은 본문을 공유하면 판본 확정을 보류한다. 확인한 문구와 근거를 결과에 남긴다.

## 입력이나 도구가 빠진 경우

- PDF만 있으면 페이지와 표시 구간을 먼저 검토한다. 원고 파일 안의 위치와 판본 확인은 원고가 들어온 뒤 진행한다.
- DOCX만 있으면 사용자 요청에 맞춰 근거와 문장 자체를 검토한다. 검사 구간이나 검사 수치는 별도 자료가 있어야 확인할 수 있다.
- 텍스트 추출이 실패하거나 도구가 없으면 현재 사용할 수 있는 PDF 보기 또는 로컬 OCR로 확인한다. PDF나 이미지에서 읽은 구간이 일부라면 검토 범위를 표시한다. 다른 포맷의 원고는 사용 가능한 읽기 방식으로 확인하고, DOCX 패키지 비교 결과로 보고하지 않는다.
- 새 검사보고서 없이 사용자가 새 수치를 알려주면 `사용자 제공`으로 기록한다. 두 검사보고서가 있으면 각각 전처리하고 판본과 검사 유형을 확인한 뒤 차이를 비교한다.
